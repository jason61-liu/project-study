# 威胁模型与安全测试

## 资产、主体与边界

资产包括授权语料、研究报告、运行记录、审批和费用数据。主体包括研究员、审批员、服务实例和 Sandbox。外部问题与来源正文均不可信；SQLite 文件、已验证身份上下文和策略代码属于受信控制面。

| 威胁 | 主要控制 | 残余风险 |
|---|---|---|
| 间接提示注入 | 来源模式检测并隔离；正文无指令权限 | 改写可绕过启发式检测，因此高风险动作仍不能由模型授权 |
| 跨租户读取 | 所有主键和查询显式包含 `tenant_id` | 应在生产数据库再加 RLS 与租户审计 |
| 凭证泄漏 | API 不接收原始 Token；摘录与输出 Secret 脱敏；Trace 无正文 | 未覆盖全部企业 DLP 类型 |
| SSRF / 本地文件 | 来源 URL 只允许 HTTP(S)；当前不主动抓取 URL | 未来抓取器必须做 DNS/重定向/私网复验 |
| 重复执行 | 租户内幂等键 + 请求哈希；冲突默认拒绝 | 幂等记录尚无归档策略 |
| 陈旧写入 | 乐观版本检查 | 多区域一致性需外部数据库 |
| 未授权审批 | 同租户且必须有 `research:approve` scope | 示例不实现 IdP、令牌撤销和强认证 |
| RCE / 资源耗尽 | 无 Shell argv、命令白名单、临时目录、超时、Linux rlimit | 本地后备不是强隔离，生产使用独立 Sandbox |
| 伪造引用 | 输出引用必须属于本次 Evidence 集 | 抽取内容是否充分支持结论仍需语义评分/人工抽检 |

`eval_harness.py` 明确定义 15 个安全场景；自动化测试覆盖 scope、跨租户读取/审批、注入隔离、Secret 脱敏、不安全 URL、语料预算、Sandbox 白名单、幂等冲突、引用校验和 Trace 隐私。生产上线前还要在真实 OAuth/OIDC 网关验证 issuer/audience/expiry/scope/撤销，并对独立 Sandbox 做断网、Secret、文件、CPU、内存、超时与销毁测试。
