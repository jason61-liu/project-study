# 评测与性能报告

环境：macOS 本机 Python 3.13.2，评测集 `business-v1`，2026-08-20。完整逐任务结果保存在 `evals/baseline.json`。

| 指标 | 结果 |
|---|---:|
| 功能任务 | 55 |
| 通过 | 55 |
| 成功率 | 100% |
| p50 延迟 | 0.704 ms |
| 总估算费用 | US$0.000986 |
| 定义的安全场景 | 15 |
| 定义的故障场景 | 10 |
| 自动化测试 | 28/28 |

该性能数字只衡量本地、确定性的单来源抽取基线，不代表联网检索或模型推理延迟。55 个任务由 11 个业务主题和 5 类问题（定义、权衡、风险、验证、上线条件）组成，适合做能力冒烟与回归门槛，不应被解释为开放域质量证明。

与人工假设基线相比，机器运行时间和直接推理成本达标，但尚未测量真实一次通过率、人工升级率和错误成本，因此发布结论仍是“有限上线”。下一阶段应使用 200 个真实、脱敏、双人标注的影子任务，每任务至少 3 次 Trial，并加入引用充分性与忠实度人工抽检。

回归门命令：

```bash
PYTHONPATH=src python3 -m deep_research_agent.eval_gate --baseline evals/baseline.json
```

候选成功率不得低于 98%，且不得比基线下降超过 2 个百分点；安全与故障场景数量也不能缩水。跨租户、未审批副作用和无效引用属于单独的硬门槛，由自动化安全测试阻断。

## 标准 Benchmark 覆盖差异

当前未宣称运行 GAIA、BFCL 或 tau-bench：本地项目没有固定版本的数据快照和对应环境，伪造一个“子集成绩”没有证据价值。业务集强调租户隔离、Checkpoint、引用与审批；GAIA 更强调开放域多步研究，BFCL 更强调函数调用契约，tau-bench 更强调有状态工具交互。正式作品集发布前应固定其中一个官方子集、记录许可和版本，并通过独立适配器运行，不能把本业务集成绩横向冒充标准 Benchmark 成绩。
