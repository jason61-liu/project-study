# SLO、容量与发布

## SLO

评测口径固定为 `business-v1`：

| SLI | 目标 / 硬门槛 |
|---|---|
| API 可用性 | 月度 99.9%（不含合法策略拒绝） |
| 已提供语料任务成功率 | >= 98% |
| 引用集合正确率 | 100% 硬门槛 |
| 跨租户泄漏 / 未审批执行 | 0，任一发生即回滚 |
| 提交 API p95 | <= 2 s（离线基线）；外部模型另设 120 s 任务时限 |
| Checkpoint 恢复成功率 | >= 99% |
| 单位成功任务成本 | <= US$0.05 |

30 天错误预算：可用性 99.9% 对应约 43.2 分钟。安全硬门槛没有错误预算。

## 容量假设

起步流量为 10,000 任务/月、工作日 8 小时内 10 倍峰值、平均 5 个来源、每来源 5 KB。平均到达率约 `10000 / (22*8*3600) = 0.0158/s`，10 倍峰值约 0.158/s。若平均端到端 5 秒，Little's Law 得峰值在途约 0.79；两个实例足够吸收单实例滚动替换。

月新增正文约 250 MB；当前仅存脱敏摘录、状态和 Trace 元数据，按任务 50 KB 估算约 500 MB/月。保留 30 天运行详情、13 个月聚合指标。SQLite 软上限设为持续 2 writes/s 或数据库 5 GB；达到任一条件，迁移 PostgreSQL，并在迁移前完成备份恢复、RLS、连接池和双写核对。

## 发布与回滚

1. 单元/集成测试和 55 条功能评测必须通过，安全硬门槛为零失败；
2. Shadow 读取生产副本但不对用户展示；
3. Canary 5% 流量，观察成功率、p95、拒答、审批和单位成本；
4. 任一安全门槛失败，或成功率下降 2 个百分点，立即把路由切回旧镜像；
5. 数据库变更必须向后兼容，先扩展后收缩；旧实例可读新 Schema 后才能滚动；
6. 回滚只切应用版本，不删除运行、Checkpoint、审批或幂等账本。

Compose 的两个实例共享状态，可用“实例 A 创建暂停任务 → 实例 B 查询并审批 → 替换实例 A → 再查询报告”演示横向扩展和滚动恢复。
