# D. 架构、规划与多 Agent（46–60）

46. 当步骤、分支、校验和副作用都能预先枚举，且可审计性和稳定性优先时，用确定性 Workflow；只在需要开放式决策时把局部交给 Agent。
47. Routing 从多个路径选一个；Parallelization 同时执行独立任务；Orchestrator-Workers 动态拆分、派发、收集与仲裁多个子任务，控制复杂度依次上升。
48. Plan-and-Execute 先形成全局计划，适合长依赖任务但计划可能过时；ReAct 每步根据观察决策，适应强但轨迹长。常用混合方式是里程碑计划加局部 ReAct。
49. 触发条件包括前置条件不再满足、外部 Artifact 版本变化、连续工具失败、预算偏差、关键假设被证伪或依赖图出现新边；触发后版本化新计划而非覆盖历史。
50. 模型自评与原生成共享偏差，可能只增加相似文字和 Token。只有外部证据、不同验证器和清晰停止条件能让反思产生可测收益。
51. 适合有明确 Rubric 且结果可迭代改进的写作、代码或方案优化。以质量阈值、最大轮数、边际增益和预算共同终止，防止无限润色。
52. Manager 中央分配任务；Handoff 转移后续控制；Agent-as-Tool 由调用者保持控制；Claude Subagent 是隔离上下文的委派；Agent Team 更接近对等协作。关键差异是最终决策权和上下文所有权。
53. 会增加 Prompt 和工具重复、Handoff 信息损失、调度延迟、冲突仲裁、循环委派、状态一致性和跨 Agent 授权面。
54. 在相同任务、模型、预算和 Grader 下做单/多 Agent 消融，多 Trial 比较成功率、p95、成本与错误类型；收益必须显著且覆盖协调成本。本项目双路代理成本翻倍而质量不变，因此不采用。
55. 建依赖 DAG，只并行无未满足前置的节点；每个输出版本化并带完成条件，汇合点校验全部输入版本，失败时只重跑受影响子图。
56. 先比较来源、时间、权限和确定性验证结果；无法消解时保留双方证据和不确定性，交给独立仲裁器或人工，不用多数票掩盖事实冲突。
57. 为任务分配稳定 ID、父子关系、深度和已完成集合；禁止重复业务键，设置最大委派深度和步数，Manager 在派发前检查 DAG 与去重账本。
58. 每阶段定义输入版本、预期 Artifact Schema、确定性不变量、质量门槛、预算和失败分类；“模型说完成”不算完成，必须检查 Outcome。
59. 状态机明确合法状态和迁移，适合强不变量；事件驱动解耦异步组件、重放和扩展。组合时事件携带版本/幂等键，状态库仍是权威源。
60. MCP 解决 Agent Host 与工具/资源/提示服务的能力互操作；A2A 解决 Agent 之间任务、身份、状态和工件协作。一个是工具边界，一个是 Agent 协作边界，控制权和生命周期不同。
