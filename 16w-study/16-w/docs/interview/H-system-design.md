# H. 系统设计与项目追问（106–120）

106. 入口校验身份、租户、Scope、Schema 和预算；分解问题，先 ACL 过滤再混合检索、去重、重排；Evidence 保存来源/版本/片段；验证冲突和引用；无证据拒答；高风险 HITL；Run/Checkpoint/Trace 全租户化，并以业务 Eval Gate 发布。
107. 把同一结构化 claim 的不同 value 与来源并列，展示时间、权威性和适用范围；不强行平均或静默择一。能按规则裁决就说明规则，不能就给不确定结论和人工升级。
108. 对同一任务集测人工/非 Agent 与候选的时间、成功率、升级率、单位成本和错误返工成本；价值是节省时间与成本减去新增错误/复核成本，安全硬失败不能用收益抵消。
109. 把任务拆成有完成条件的 DAG；长调用后及副作用前后写原子 Checkpoint；Worker 用 lease/heartbeat/fencing；在途调用有幂等键和 Effect Ledger；恢复先对账、刷新授权和证据版本，再继续或重规划。
110. 将总预算分到规划、检索、工具、生成和收尾；每步原子扣账，预估下一动作成本，超限前降级、缩小范围或拒答；Trace 记录实际 Token/费用，禁止无限反思。
111. 先按任务风险/复杂度用确定性规则路由，低成本模型处理简单任务，高质量模型处理复杂或失败升级；固定模型快照，用分桶 Eval 和在线 Shadow 校验，路由置信不足宁可升级而非静默降质。
112. 建依赖 DAG，并行节点各写独立版本化 Artifact；使用稳定 call ID 和幂等键；汇合点以 CAS 校验输入版本后原子提交，部分失败只取消/重试未完成分支。
113. 客户端并发限制、超时、尊重 Retry-After、指数退避加 Jitter、熔断和全局重试预算；可降级到缓存、备用模型或抽取式基线，高风险质量不足则拒答而不是无提示降级。
114. 每次 Run 记录 Prompt 哈希、模型快照、Tool Schema、MCP、记忆策略和 Eval 版本；CI 先测试与回归 Gate，再 Shadow、Canary、逐级放量；Schema 向后兼容，安全失败或质量下降 2 点自动回旧版本并保留审计。
115. 固定任务与模型，对全量和压缩上下文运行多 Trial，比较关键事实召回、引用覆盖、忠实度、任务成功率和 Token/延迟；否定、数字、时间和少数观点做专门切片，置信区间跨过允许损失才通过。
116. `单位成功任务成本 = 所有 Trial 的模型 + 工具 + Serving + 人工复核 + 失败返工成本 / 严格成功任务数`。失败成本留在分子，不能只算成功调用的 Token。
117. 本项目最重要失败是错误 Grader：上下文被截断后，报告问题段仍回显主题，导致误判 100% 成功。定位到判定对象错误，改为检查 Evidence excerpt 后重跑得到 0%，并把该案例加入回归。
118. 未采用多 Agent。双路代理消融质量仍 100%，但成本翻倍、延迟约增加 58%；固定流程没有动态分工价值，额外协调只扩大恢复和安全面。
119. 首先是 SQLite 单写锁和同步请求模型，然后是外部检索/模型限流与尾延迟。迁移 PostgreSQL、异步队列和独立 Worker，做 backpressure、分层限流、连接池与水平扩展，并用 Little's Law 重新容量规划。
120. 结构化反馈类别、升级原因、Online KPI 与 Trace 关联；失败/高风险全审、成功抽样；脱敏去重、双人裁决后进入候选集，固定 holdout 隔离；对新增失败重放 Offline Eval，只有线上线下同向且安全 Gate 通过才发布，同时支持 provenance 和删除。
