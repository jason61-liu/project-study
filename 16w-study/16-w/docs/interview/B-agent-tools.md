# B. Agent 基础与工具（16–30）

16. Agent 是“模型 + 状态 + 工具 + 控制循环”，可观察环境并采取动作；Workflow 的路径主要由代码确定，Chatbot 偏对话，RAG 是检索增强机制而非完整控制循环。
17. 最小 Loop 需要目标、消息/业务状态、允许工具、Observation、步数/时间/Token/费用预算，以及 completed、refused、failed、cancelled 等显式终态。
18. ReAct 交替推理、行动和观察，能根据工具结果修正；典型失败是轨迹膨胀、循环调用、错误观察放大和把推理文本当授权。
19. 结构化输出约束模型最终数据形状；工具调用是模型提出由 Runtime 执行的动作。二者都需 Schema，但工具还需要授权、幂等和副作用收据。
20. Schema 越宽，模型可选空间和非法组合越多，校验与权限边界也越模糊；最小枚举、必填字段和封闭对象更可靠安全。
21. 错误应结构化为可重试性、错误类型、稳定代码、已提交/未提交/未知、建议退避和用户可修复字段；不要把任意错误文本直接变成新指令。
22. 纯读取在一致性允许时通常可重试；创建、付款、通知等副作用必须用绑定业务意图的幂等键。超时后状态未知时先对账，不能直接重放。
23. Runtime 在执行前按工具 allowlist 和 JSON Schema 拒绝，返回结构化 `unknown_tool` 或 `invalid_arguments`；计入尝试预算，允许有限自修复，重复失败就终止或升级人工。
24. 每次动作同时扣步数、Token、费用和墙钟预算，任一触底即停止；给关键收尾预留预算，外部调用还要有分层超时，不能只依赖最大步数。
25. 工具结果可能含提示注入、过期数据、跨租户内容、Secret 或伪造成功。它只有数据权限，没有指令权限，必须做来源、Schema、租户和输出裁剪。
26. 模型只提交结构化意图，Runtime 持久化参数摘要、风险、资源版本和审批义务；审批绑定用户、租户、动作、哈希和有效期，批准后再由 PEP 执行，参数变化使批准失效。
27. Function Calling 是模型与宿主之间的结构化调用表示；MCP 是 Host/Client/Server 间发现和调用工具、资源、提示的协议。MCP 可以承载工具，但不替代模型调用格式和业务授权。
28. Host 是用户侧应用和信任根，管理模型、权限与多个连接；Client 维护到一个 Server 的协议会话；Server 暴露并执行 Tools、Resources、Prompts。
29. Tool 通常由模型选择并产生动作，Resource 由应用读取上下文，Prompt 多由用户显式选择模板。三者控制权和风险不同，不能都当无条件模型工具。
30. 用户是资源所有者，Agent/客户端代表用户发起，Authorization Server 签发受众和 Scope 有限的 Token，Resource Server 最终校验。只把凭证交给目标工具通道，模型上下文只见最小身份引用；支持短期 Token、撤销和逐次授权。
