# F. 安全与可靠性（76–90）

76. 直接注入来自用户明确输入，间接注入藏在网页、邮件或工具结果中。间接注入更易跨信任边界且会伪装成任务数据。
77. Prompt 是给概率模型的文本，能被冲突、改写或误解；权限必须由模型无法绕过的身份验证、Schema、PDP/PEP、资源服务器和 Sandbox 强制。
78. 功能风险是给了不必要工具；权限风险是工具 Scope/资源过宽；自主性风险是无需确认即可长时间或高影响执行。三者分别用能力裁剪、最小权限和预算/HITL 控制。
79. OIDC 建身份，OAuth 委托最小 Scope；RBAC 给角色基础权限，ABAC 再约束租户、资源、金额、风险和目标；短期凭证只传工具通道，Resource Server 复验 audience/expiry，撤销后恢复任务必须重新授权。
80. 把输出标记为无指令权限的 Observation，做 Schema、来源、租户和 Secret 检查，只提取任务需要字段；任何高风险动作仍重新走 PEP，不能继承工具文本中的要求。
81. 上下文只放最少数据，日志默认内容关闭，输出做 DLP；凭证用引用和专用通道。用两个租户的 canary 标记分别测试 RAG、状态、记忆、缓存、Trace、导出和删除，任何交叉命中都是硬失败。
82. 容器启动快、密度高但共享内核；微虚机隔离更强、冷启动和资源开销更大。按威胁等级选，执行未知代码通常优先强隔离并限制网络、挂载和 Secret。
83. 选型看隔离原语、托管/自建、SDK 兼容、网络策略、文件系统、资源限额、审计、冷启动和销毁证明。E2B 兼容减少 API 迁移成本，但不自动保证相同隔离强度、运营安全或策略语义。
84. 投放带错误事实和恶意目标的记忆候选，验证未经审批不写入、跨租户不召回、冲突不覆盖、删除后无残留；Goal Hijack 测试外部内容能否改变任务目标或触发未授权工具。
85. 重试处理暂态失败，幂等保证重复意图不重复效果，补偿处理已提交但后续失败的语义逆动作。三者组合仍不是全局 Exactly-once。
86. 无 Jitter 时大量客户端按同一指数周期同时重试，形成同步尖峰；随机化退避把请求摊开，降低再次压垮依赖的概率。
87. 依赖失败引发各层、各副本和队列同时重试，放大流量。用单层重试、总预算、指数退避加 Jitter、Retry-After、并发限制、熔断和降级阻止。
88. 超时不等于未提交。记录 call ID、幂等键和 Effect Ledger，恢复时向权威系统对账为 committed/not committed/unknown；未知则人工处理，不盲目重放。
89. 至少包括时间、trace/run/task、租户/用户伪名、动作/工具/模型版本、Schema/Prompt/策略版本、授权决定、审批、幂等键摘要、输入输出哈希、状态迁移、Token/费用/延迟、错误和副作用收据；正文默认不记。
90. 在可控点注入超时、响应丢失、锁竞争、进程崩溃、限流、陈旧版本、权限撤销和部分提交；断言最终 Outcome、无重复效果、恢复路径、预算、Trace 与人工升级，而非只断言“捕获异常”。
