# C. 上下文、RAG 与记忆（31–45）

31. 上下文工程是在预算内选择、组织、隔离和压缩最相关信息，并保留来源与优先级；单纯增加文本会提高噪声、成本和注入面。
32. 大 Chunk 保留语义完整但召回粗、噪声大；小 Chunk 精准但上下文断裂。Overlap 减少跨边界丢失，却增加索引、重复召回和 Token，需按任务调参。
33. 稀疏检索擅长精确词、编号和新实体；稠密检索擅长语义改写；混合检索在两类信号都重要时更稳，但需要融合和校准。
34. Reranker 对初召回候选做更精细的 query-document 相关性排序，提高 top-k 精度；代价是额外模型延迟、费用和截断偏差，不能弥补初召回完全漏掉。
35. Recall@K 看相关文档是否进前 K，MRR 看首个相关结果排名；忠实度看回答是否由证据支持；引用正确率看引用是否真实支持对应陈述。它们不可互相替代。
36. 无答案要拒答；冲突要并列来源与版本；过期证据降权或阻断；ACL 必须检索前过滤；增量更新用版本和 tombstone，删除后检查索引、缓存与备份残留。
37. History 是交互上下文，Checkpoint 是恢复状态，长期记忆是跨会话事实，业务状态有权威数据库，Prompt Cache 复用输入计算，KV Cache 是推理中间张量。生命周期、正确性和权限完全不同。
38. 只保存稳定、用户有价值、可纠正、带来源且经授权的偏好或事实；不要保存临时推理、未核验网页内容、Secret、敏感推断和业务权威数据副本。
39. 摘要会丢限定条件、否定、数字、时间、来源和少数意见。用原文对照的关键事实召回、下游任务成功率、引用覆盖和反事实边界集评测。
40. Mem0 提供抽取与生命周期能力，接入快但多一层依赖和黑盒策略；自建向量记忆控制强但工程成本高。共同评测抽取精度、Recall@K、错误更新、删除、租户隔离与污染恢复。
41. 写入前做来源和审批，记忆记录 provenance、版本、置信度和 TTL；冲突不覆盖而是并存待裁决；提供删除、回滚、隔离区和污染回归集。
42. 大窗口仍有位置偏差、噪声、成本和权限问题。检索让证据可更新、可删除、可引用；压缩让模型把预算集中在关键事实。
43. 先为系统指令、用户目标、工具 Schema、证据和输出分别预留硬预算；按任务价值动态分配，超限优先去重和检索，再做可评测压缩，并留收尾余量。
44. LangGraph Store 适合图运行相关的跨线程命名空间状态；Mem0 适合抽取后的用户事实记忆；Deep Agents 文件上下文适合长任务工件和子 Agent 共享。业务权威数据仍留在业务库。
45. 每条 Evidence 有稳定 ID、来源 URL、版本和原文片段；报告只能引用本次集合；确定性 Grader 检查 ID 存在、用户有权访问，并验证引用片段是否蕴含对应陈述。
