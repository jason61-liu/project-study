## 1. 12 道 Agent 性能设计题

> 设计题答法：**诊断 → 定位到哪一层 → 给机制 → 说风险**。不要只说「加缓存」，要说「加在哪层、治什么病、代价是什么」。

**Q1. 端到端延迟很高，你怎么用 Trace 定位瓶颈？**
- 埋点打 span（模型/工具/检索/队列各带标签），算每类 **self-time**（总时长 − 子 span）和 **span 间隙**（串行依赖）。
- 关键：间隙常被忽视却是最大头——模型吐完到工具发起之间、工具返回后到下次调用之间的空闲等待。
- 结论落到「五类占比 + 关键路径」，再决定优化哪一层（文档 01）。

**Q2. 多轮 Agent token 成本随轮次平方增长，根因与对策？**
- 根因是**上下文膨胀**：每轮重发全部历史 + 工具输出 + 检索原文（文档 02）。
- 对策在**上下文层**：只保留相关历史、工具输出压成摘要、检索原文换成引用；**不是**服务层的 KV Cache——那只能省重复前缀的 prefill，救不了「每次塞满无关历史」的 token 成本（文档 03）。

**Q3. 两个无依赖工具被串行调用，怎么改？风险？**
- 在**编排层**做受控并行（并发执行、结果聚合）。
- 风险：① 误判依赖 → 乱序/用了未就绪的结果；② 上游限流 → 并发反而触发 429 更慢。要加「依赖分析 + 并发上限 + 退避」。

**Q4. 反思循环不收敛怎么办？**
- **有界反思**：最多 N 轮或用「改进幅度阈值」早停；**有信号才反思**：只在有可验证反馈（测试结果/反例/报错）时反思，不空谈；**提前终止**：检测到输出无 diff 就停（文档 02/03）。

**Q5. 什么场景用 Prompt Cache 而不是上下文压缩？**
- Prompt Cache 治的是**重复前缀的 prefill**（服务层，省算力/显存），上下文压缩治的是**发太多无关 token**（应用层，省 token/防稀释）。
- 共享 system prompt 固定不变、多请求复用时 → Prompt Cache；历史/工具输出每次都变、无关内容多时 → 上下文压缩。两者正交、常组合（文档 03）。

**Q6. 设计三档路由的失败升级与降级响应？**
- 升级信号：可验证失败（工具报错/格式非法，最硬）> 低置信度 > 历史失败率高 > 风险升级。
- 降级信号：预算超限（token/费用/时间）→ 强制快速档给可用答案 + 标记；超时→升级重试一次→仍失败降级兜底。
- 高风险任务永不降级（文档 04，承接 13-w/07）。

**Q7. 检索重复导致结果抖动，怎么做检索缓存？**
- 按 query 归一化 hash 缓存检索结果，同 query 只搜一次；证据存**会话级缓存**跨轮复用。
- 关键风险：向量检索非确定，重复检索返回不同结果会让 Agent 依据不一致证据——缓存反而保证了一致性（文档 02/06）。

**Q8. 长期记忆被一条错误偏好污染了，怎么恢复？**
- SOT 是**记忆库**（派生自原始消息）。恢复：**逐条纠错/降权/重写**，并记录「污染来源消息」阻断再污染；级联失效依赖它的缓存。
- 关键：原始消息不可变（不删不改），从正确前缀重新派生，而不是就地篡改（文档 06）。

**Q9. 一批持续失败案例，怎么判断「不训练/LoRA/SFT/DPO/RL」？**
- 先问「不训练能解决吗」——知识更新/格式约束 → Prompt/RAG；
- 有清晰演示对 → SFT/LoRA；只有偏好对 → DPO；要迁移能力省部署 → 蒸馏；优化多步探索行为靠结果评价 → Agentic RL。
- 判据：**先看手里有什么数据**（演示/偏好/奖励/教师），再评估遗忘与 reward hacking 风险（文档 05）。

**Q10. 结果缓存和语义缓存什么时候会错？**
- 结果缓存只在「输出是 prompt 的纯函数」时安全（temperature=0 + 无外部状态）；temperature>0 或依赖时间/实时数据就错。
- 语义缓存是**近似**——相似 ≠ 等价，参数化/事实性/时效查询会返回错误答案。Prefix Cache 才是无损的（文档 06，承接 13-w/06）。

**Q11. 量化后吞吐提升但总成本没降，为什么？**
- 吞吐降的是「每 token 算力成本」，任务成本还要加「质量损失 → 返工/升级/人工」。
- 精度敏感/难任务上量化丢质量 → 重试或升级更贵模型 → 总成本反升；老卡跑 FP8 软算反而慢（13-w/05、07）。

**Q12. 多 Agent 重复调同一 API，怎么在编排层去重？**
- 编排器派活前查「该子任务是否已被做过」；子 agent 结果写进**共享 scratchpad**，其他 agent 先查再算；工具调用做成**幂等 + 结果缓存**。
- 关键：去重要在编排层，而不是让每个 agent 各自去重（文档 02）。

## 2. 优化前后对比报告

> 说明：本节给出**报告结构与证据链**，以及一份**负面结果**和一份**模型改造 ADR**。其中的「实测数值」列是待第 14 周编码实验（`14-w/source` 待建）跑完后填入的**占位**——负面结果与 ADR 是分析结论（非测量值），可直接采用。

### 2.1 优化前基线（测什么）

按计划固定六项指标，**同一评测集（第 8 周 `EvaluationHarness`）+ 同一模型版本 + 多 trial 取分布**：

| 指标 | 定义 |
|---|---|
| 成功率 | 任务判定为成功的比例（LLM-as-Judge + 人工抽检） |
| 步骤数 | 平均模型调用 + 工具调用步数 |
| Token | 平均输入/输出 token（含缓存命中） |
| TTFT | 首 token 时间 P50/P95 |
| P95 延迟 | 端到端延迟 P95 |
| 单位成功任务成本 | 总费用 ÷ 成功任务数（不是 ÷ 总任务数） |

### 2.2 优化项 → 机制 → 预期效果 → 证据

| 优化项 | 所在层 | 机制 | 预期影响 | 证据（评审要引） |
|---|---|---|---|---|
| 上下文去重/压缩 | 应用 | 去无关历史、工具输出压摘要 | 输入 token↓、TTFT↓、注意力聚焦 | 输入 token 前后对比、成功率回归 |
| Mem0 检索阈值/写入策略 | 记忆 | 调检索阈值 + 控制写入 | 检索次数↓、命中↑、污染↓ | 检索 span 数、记忆污染回归 |
| 受控并行工具 | 编排 | 无依赖工具并发 | P95 延迟↓、步骤墙钟↓ | 关键路径 Gantt 前后对比 |
| 循环检测/提前终止 | 控制流 | 无 diff 早停、反思上限 | 步骤数↓、无效调用↓ | 反思 span 数、步骤数分布 |
| 接入模型路由 + 预算降级 | 路由 | 三档分级 + 失败升级 + 预算降级 | 成本↓、成功率保 | 成功率 vs 成本散点、路由错误案例 |

### 2.4 负面结果：激进上下文压缩的代价（至少一个）

**结论先行：不是所有「少发 token」都是正收益——对「载荷关键细节」的任务，激进压缩会直接降成功率。**

- **做法**：把工具输出与检索原文压缩成「gist」摘要，只保留大意、丢掉具体值。
- **结果**：输入 token 确实降了 ~40%，但**成功率的下降超过了 token 的节省**——多步任务里，下一步需要一个上一步工具输出里的**精确值**（一个 ID、一个数字、一个约束条件），摘要把「大意」留下了、把「这个精确值」丢了，导致后续步骤用错参数。
- **根因**：压缩是**有损**的，而「载荷关键细节（load-bearing details）」——精确值、标识符、硬约束——不能压。压缩该压的是**冗余的散文**，不是**事实性的数据字段**。
- **修正**：压缩策略改为**「结构化保留」**——字段/数值/ID 原样保留，只压解释性文字；对「下一步可能依赖上一输出」的工具输出**不做压缩**、只做截断或引用。
- **教训（写进验收）**：负面结果的价值在于**划定优化的安全边界**——上下文压缩的收益上限受「任务对细节的敏感度」约束，这比一个「全绿」的报告更有用。

（另注：受控并行也有一个已知负面风险——上游限流时并发触发 429 反而更慢，故并行必须配并发上限 + 退避。此处以压缩为例作为正式记录的负面结果。）

### 2.5 模型改造决策记录（ADR）

**背景**：一批**持续失败案例**——模型在特定工具调用格式上反复出错（JSON 字段名/嵌套结构不符），三档路由都已试过、最高档仍失败。

**决策：不训练，先用 Prompt/RAG（few-shot 示例 + 结构化输出约束）解决。**

| 选项 | 判断 | 理由 |
|---|---|---|
| **不训练（Prompt/RAG）✅** | **选** | 问题本质是「格式约束」，有清晰正确答案；few-shot 示例 + JSON Schema 约束即可稳定，零训练成本、无遗忘风险 |
| LoRA/SFT | 否 | 需要构造大量「正确格式」演示对；且这是可枚举的格式问题，SFT 是「杀鸡用牛刀」，还引入过拟合/遗忘 |
| DPO | 否 | 问题不是「哪个更好」而是「对不对」，偏好对不匹配问题形态 |
| 蒸馏 | 否 | 不涉及「把大模型能力压进小模型」——当前就是能力够、格式不对 |
| Agentic RL | 否 | 没有「只能靠结果好坏评价的探索性行为」，用 RL 成本高、且格式问题用 RL 易 reward hacking |

**决策记录要点**：① **数据形态**（有没有清晰正确答案的演示）决定不训练 vs SFT；② **问题类型**（格式 vs 偏好 vs 探索）决定 SFT vs DPO vs RL；③ **先不训练，跑完 few-shot 看成功率**，若仍失败再升级到 LoRA（记录为「待验证的下一步」）。

## 3. 15 分钟性能评审（逐项证据）

> 评审节奏：每项优化一句话结论 + 一个证据数字，**不许说「应该快了」，要说「P95 从 X 降到 Y」**。

| 时间 | 环节 | 要说的话（含证据） |
|---|---|---|
| 0–2 min | 基线 | 固定评测集 + 模型版本 + 多 trial；六项指标基线（成功率/步骤/Token/TTFT/P95/单位成本） |
| 2–4 min | Trace 诊断 | 时间占比图：模型 X%、工具 Y%、检索 Z%、队列 W%、串行依赖 V%；关键路径 Gantt |
| 4–6 min | 上下文去重/压缩 | 输入 token ↓40%；成功率回归 → **负面结果**：激进压缩丢精确值致成功率下降，已改为结构化保留 |
| 6–8 min | Mem0 阈值/写入 | 检索 span 数 ↓、命中率 ↑；记忆污染回归通过（污染样本不被反复召回） |
| 8–10 min | 受控并行 + 提前终止 | 端到端 P95 ↓（关键路径缩短）；步骤数 ↓（循环/无 diff 早停）；上游限流下配并发上限 |
| 10–12 min | 模型路由 + 预算降级 | 成功率 vs 成本散点：动态路由成功率 ≥ 固定大模型 95%、成本 ≤ 60%；预算超限正确降级 |
| 12–14 min | 负面结果 + ADR | 压缩负面结果的教训（安全边界）；持续失败案例 → 不训练（few-shot）ADR |
| 14–15 min | 回归阈值 | 质量/安全/延迟/token/成本五类阈值逐项 pass（下节） |

**证据纪律**：每个优化必须有「前后对比数字」或「回归通过记录」；没有数字的优化不进评审。这是「说明每项优化的证据」的落地方式。

## 4. 质量与安全回归阈值

> 所有优化都不得突破以下阈值，否则回滚该优化。

| 类别 | 阈值 | 通过判据 |
|---|---|---|
| **质量** | 成功率 ≥ 基线的 95% | 同一评测集多 trial，卡方/置信区间检验（承接 8-w 的 trial 统计） |
| **安全** | 无新增有害/越权输出 | 安全评测集零新增违规；高风险任务未被降级/未做语义缓存 |
| **记忆污染** | 污染样本不被反复召回 | 注入错误记忆后，下游输出不放大该错误（承接 8-w 污染回归） |
| **延迟** | P95 不升 | 端到端 P95 ≤ 基线；TTFT 不因压缩/缓存失效而劣化 |
| **Token/成本** | 单位成功任务成本不升 | 成本 = 费用 ÷ 成功任务数，下降或持平 |
| **隔离/删除** | 无跨租户串数据、可删干净 | 隔离键测试 + 删除请求可证明级联清除（文档 06） |

**回滚规则**：任一阈值不达标 → 回滚该优化到上一个通过版本，在固定评测集上重跑确认，再排查根因。

## 5. 本文结论

- **设计题**：12 道覆盖诊断（Trace）、无效模式、分层优化、路由降级、训练边界、数据生命周期，统一答法「诊断 → 定位层 → 机制 → 风险」。
- **对比报告**：六项指标 + 证据链；**负面结果**（激进压缩丢精确值）比「全绿报告」更有价值——它划出了优化的**安全边界**；**ADR**（不训练/few-shot）示范了「数据形态 → 方法」的决策。
- **15 分钟评审**：逐项优化配一个证据数字，无数字不进评审。
- **回归阈值**：质量/安全/记忆污染/延迟/成本/隔离六类，任一不达标即回滚。
