# 量化精度比较：FP16 / BF16 / FP8 / INT8 / INT4 与权重、激活、KV Cache 量化

> 目标：把「精度格式」和「量化对象」两件事分开看——先比 FP16/BF16/FP8/INT8/INT4 的表示范围、精度和硬件门槛，再区分权重、激活、KV Cache 三类量化的敏感度与显存收益。核心结论是：**量化不是免费的，收益（显存/带宽）和风险（精度/质量）因「量化谁」而天差地别**。

---

## 1. 阅读前术语表

| 术语 | 说明 |
|---|---|
| 浮点格式 | 符号位 + 指数位 + 尾数位；指数定范围、尾数定精度 |
| 定点/整型 | INT8/INT4，值域窄，需 scale（量化因子）缩放 |
| 量化 | 把高精度张量映射到低 bit 表示，推理时反量化回高精度算 |
| 动态范围 | 能表示的最大/最小值区间，决定会不会溢出/下溢 |
| 对称/非对称量化 | 只用 scale，还是 scale + zero-point |
| 分组量化 | 按 channel/group 分块各用各的 scale，缓解离群值影响 |
| W8A8 / W4A16 | 权重 8bit/激活 8bit、权重 4bit/激活 16bit 等组合 |
| 硬件门槛 | 该格式是否有对应 Tensor Core 加速，否则软算反而慢 |

---

## 2. 五种精度格式的表示能力

| 格式 | 符号/指数/尾数 | 大致范围 | 精度 | 硬件要求 |
|---|---|---|---|---|
| **FP32** | 1/8/23 | ±3.4×10³⁸ | 高（~7 位十进制） | 全部支持 |
| **FP16** | 1/5/10 | ±65504 | 中（~3–4 位） | 全部支持（Tensor Core） |
| **BF16** | 1/8/7 | ±3.4×10³⁸（同 FP32） | 低（~2–3 位） | **Ampere+（A100）** |
| **FP8 (E4M3)** | 1/4/3 | ±448 | 低但细（尾数多） | **Hopper+（H100）** |
| **FP8 (E5M2)** | 1/5/2 | ±57344 | 低（尾数少、范围大） | **Hopper+（H100）** |
| **INT8** | 8bit 整数 | −128…127 | 中（均匀 256 级） | 广泛（Tensor Core） |
| **INT4** | 4bit 整数 | −8…7 | 很低（16 级） | 有限（需专门指令/新架构） |

要点：

- **BF16 的卖点是「范围」**：指数位和 FP32 一样（8 位），所以**不会像 FP16 那样在累加/大数时溢出**，代价是尾数少、精度糙。这就是训练普遍用 BF16 而不是 FP16 的原因——训练更怕溢出而不是怕尾数误差。
- **FP8 分两种**：E4M3 尾数多、适合前向的权重/激活；E5M2 范围大、适合梯度（梯度动态范围大）。DeepSeek-V3 的 FP8 训练（文档 02）就是 E4M3 做 GEMM + FP32 累加。
- **INT4 只有 16 个值**，必须靠分组量化（每 32/64/128 元素一个 scale）才能勉强不崩，是「极限压缩」档。

## 3. 三类量化对象的敏感度完全不同

量化「谁」，收益和风险差别极大：

### 3.1 权重量化（最稳，收益主要省显存）

- 权重是**静态、已知分布**的，可以离线做（甚至校准 + 训练后量化 + 量化感知训练 QAT），敏感度最低。
- 典型：**W8A16**（权重 INT8、激活 FP16）几乎无损；**W4A16**（AWQ/GPTQ）能把显存压到 1/4，质量略有下降。
- 收益：**模型加载显存**与**推理时读权重的带宽**下降，对大模型（尤其 MoE 的 671B 权重）是刚需。

### 3.2 激活量化（最敏感，收益省算力）

- 激活是**动态、逐 token 变化**的，分布有离群值（outlier），直接量化会崩。
- 需要**动态量化**（运行时算 scale）或 **SmoothQuant**（把量化困难从激活转移到权重）。
- 典型：**W8A8**（权重 INT8 + 激活 INT8）才能真正吃到 **INT8 Tensor Core 的 2× 算力**——只量权重不量激活，算力不翻倍。
- 收益：算力/带宽都降；风险：激活离群值导致精度损失最明显。

### 3.3 KV Cache 量化（收益省显存，长上下文刚需）

- KV Cache 是**长上下文/高并发下最大的显存占用**（文档 12-w/01、02），量化成 FP8/INT8 能把 KV 显存近乎减半。
- KV 是「读多写少、对误差相对不敏感」的中间结果，量化相对安全；DeepSeek 的 FlashMLA 稀疏 decode 就默认 **FP8 KV Cache**。
- 收益：**显存**（不是算力）——能装更长的上下文、更大的 batch；风险：长序列累积误差可能影响生成质量。

一句话总结：**权重量化省显存、激活量化省算力但最敏感、KV 量化省显存且长上下文收益最大**。

## 4. 「精度—显存—硬件」三者怎么一起看

| 组合 | 显存（相对 FP16） | 算力 | 硬件门槛 | 典型用途 |
|---|---|---|---|---|
| FP16 | 1× | 1× | 全 | 默认推理 |
| BF16 | 1×（同 16bit） | 1× | A100+ | 训练/推理通用 |
| W8A16 | ~0.5× | ~1× | 广泛 | 省显存的权重量化 |
| W8A8 | ~0.5× | ~2× | 广泛 | INT8 全量化，吃算力红利 |
| FP8 (W8A8) | ~0.5× | ~2× | **H100+** | 高性能推理/训练（V3） |
| W4A16 | ~0.25× | ~1× | 有限 | 极限省显存（AWQ/GPTQ） |

要点：

- **显存省多少取决于「权重还是 KV」**：权重量化省的是模型体积，KV 量化省的是运行时缓存——对长上下文，后者往往更关键。
- **算力红利只在「权重+激活」都量化时才兑现**（W8A8/FP8 才有 2× GEMM）；只量权重（W8A16）是「省显存不省算」。
- **硬件是硬门槛**：FP8 要 H100 的 E4M3 Tensor Core，老卡（V100/A100）跑 FP8 只能软算反而更慢；BF16 要 A100 起。**「量化后吞吐提升」不是所有卡、所有任务都成立的**——这正是第 13 周面试要答的「为什么量化后吞吐提升 ≠ 所有任务成本都下降」。

---

## 5. 本文结论

1. **格式之间是「范围 vs 精度」的取舍**：BF16 靠大范围防溢出（适合训练），FP8 靠细分块做 GEMM（适合 Hopper 推理/训练），INT8/INT4 靠分组量化极限压缩。
2. **量化对象决定收益与风险**：权重最稳（省显存）、激活最敏感（省算力但易崩）、KV 最划算（长上下文刚需、省显存）。
3. **算力红利有条件**：只有权重+激活同时量化（W8A8/FP8）才吃到 2× Tensor Core；只量权重只省显存不省算。
4. **硬件门槛决定能否兑现**：FP8→H100+、BF16→A100+、INT4→新架构；老卡上量化可能软算反而更慢。

这套「格式 × 对象 × 硬件」的框架，是评估任何量化方案（AWQ/GPTQ/SmoothQuant/FP8）的统一坐标。
