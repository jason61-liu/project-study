## 1. 14 道面试题：从产品名落到机制与约束

> 每题统一结构：**产品名 → 机制 → 约束/代价**。面试先给「机制」一句话，再补「约束」。

### 1.1 DeepSeek / Kimi 类

**Q1. DeepSeek-V3 的 MLA 为什么能省 KV Cache？约束是什么？**
- **机制**：把每个 token 的 K、V 低秩压缩成一个 latent 向量 `c_KV`（远小于完整 KV），显存只缓存这个压缩态，注意力时**即时上投影**回 K/V。
- **约束**：① 上投影是额外逐 token 算力，需 FlashMLA 这类专用 kernel 融合才不亏；② 隐含「KV 低秩」假设，秩不够则压缩有损；③ 硬件门槛 SM90/100、CUDA 12.8+。

**Q2. DeepSeekMoE 的「细粒度专家 + 共享专家」与普通 MoE 差别？共享专家解决什么？**
- **机制**：专家切得更小、数量更多（细粒度），每个 token 只激活 top-k；另加几个**共享专家**被所有 token 无条件激活，承载通用知识。
- **约束**：需要路由网络（gating），引入「选错专家」与负载均衡问题；推理时专家需按需加载，对专家并行/显存管理有额外要求。

**Q3. DeepSeek-V3 的「辅助损失自由负载均衡」怎么做到不损质量？**
- **机制**：传统做法在 loss 里加辅助损失强制均衡，会**损害模型质量**。DeepSeek-V3 改成给每个专家加**可学习路由偏置 `b_i`**，偏置按「近期使用频率」动态调（用得多→减小、用得少→增大），只影响「谁被选中」、不影响梯度。
- **约束**：偏置是经验式调节而非优化目标保证，引入更新步长等超参，且仍有「均衡程度」的取舍。

**Q4. MTP 训练和推理各有什么收益？和推测解码怎么挂钩？**
- **机制**：主干外接多个顺序预测头，训练时**同时预测未来 D 个 token**，每位置多一步监督 → 提数据效率；MTP 模块（约 14B 权重）在推理时可丢弃，也可**直接当推测解码的 draft 模型**（用同主干猜下一个 token）。
- **约束**：额外预测头带来额外参数与训练算力；MTP 头与主干目标有细微差异，需独立 RMSNorm/投影对齐。

**Q5. DeepSeek-V3 用 FP8 训练凭什么不崩？硬件要求？**
- **机制**：E4M3 做 GEMM 输入 + **FP32 高精度累加**；用**细粒度量化**（1×Nc tile、Nc=128 分组各带独立 scale）缓解 FP8 动态范围小；对归一化/softmax/MoE 门控等敏感算子保留 BF16/FP32。
- **约束**：量化工程复杂度高；需 Hopper（SM90）的 E4M3 张量核心，老卡软算反而慢。

**Q6. GRPO 相比 PPO 省了什么？代价/局限？**
- **机制**：PPO 需训练同规模的 critic（value 网络）估 advantage，**显存翻倍**；GRPO 用「组内相对比较」替代 critic——每组采样 G 个回答，`advantage = (r_i − 组内均值)/组内标准差`，加概率比裁剪 + KL 惩罚。
- **约束**：advantage 是**序列级**（无逐 token 功劳分配）；组内全对/全错时梯度为零；天然偏向更长回答。这些是 DAPO 等后续算法要补的坑。

**Q7. DeepSeek-R1 为什么先训大 R1 再蒸馏，而不是直接对小模型做 RL？**
- **机制**：R1 先冷启动 SFT → 推理 RL → 拒绝采样 80 万样本 SFT → 对齐 RL；再用 R1 数据 SFT 蒸馏到 Qwen/Llama 小模型。
- **约束**：**蒸馏比直接小模型 RL 更有效**——因为推理的涌现需要大模型容量，小模型直接 RL 学不会，但能靠大模型数据「抄作业」。代价是蒸馏上限受教师模型能力封顶。

**Q8. DSA 和 FlashMLA 分别是什么？DSA 是精确还是近似？**
- **机制**：DSA（DeepSeek Sparse Attention）用 **lightning indexer** 选每个 query 关注的 top-k token，注意力只在这批 token 上算；FlashMLA 是 MLA 的优化内核，同时提供 dense/sparse 两种 kernel（sparse 即实现 DSA）。
- **约束**：DSA 是**近似**（top-k 之外的重要 token 可能被漏掉），索引器本身有开销，需专门稀疏内核才跑出速度；FlashMLA 是精确内核但门槛 SM90/100。

**Q9. Kimi K2 的 MuonClip 里的 QK-Clip 是干嘛的？**
- **机制**：MuonClip = Muon 优化器 + **QK-Clip** 权重裁剪。QK-Clip 裁剪 Q/K 投影权重，把注意力 logit 的绝对值限制在一定范围，防止 1T 规模训练后期 logit 爆炸导致不稳定。
- **约束**：直接放大 Muon 会不稳定，QK-Clip 是「经验性稳定化」，裁剪强度是敏感超参，且主要针对大 MoE 的 logit 爆炸问题。

**Q10. Kimi Linear 的 KDA 是什么？混合线性注意力为什么 3:1 交错？**
- **机制**：KDA（Kimi Delta Attention）是线性注意力，在 Gated DeltaNet 基础上加**逐通道门控**，用「固定大小状态 + 递归更新」替代 O(N²) softmax，KV Cache 压缩进固定状态；混合架构让 KDA 层与全局 MLA 层 **3:1 交错**，少数精确 MLA 层兜底长程召回。
- **约束**：线性注意力是**近似**（长程精确召回弱于全注意力）；1M 上下文下 KV 省 75%、解码快 ~6×，但超大模型规模化仍存疑（K2 Thinking 未用 KDA、MiniMax M2 回退全注意力）。

**Q11. Kimi k1.5 的 partial rollout 解决什么？**
- **机制**：长上下文 RL 的瓶颈是「每个新采样都要从头生成整条长轨迹」。partial rollout 把轨迹**切段存 replay buffer**，新采样复用旧片段（iter n−m…n−1）、只生成新尾部；顺带做重复检测 + 早停惩罚。
- **约束**：轨迹分段/重放的工程复杂度高；复用旧片段可能引入分布漂移，需要配合重复惩罚与采样策略控制。

### 1.2 量化类

**Q12. FP8 的 E4M3 和 E5M2 分别用在哪？为什么？**
- **机制**：E4M3（1/4/3）尾数多、精度细但范围小（±448），适合**前向的权重/激活**；E5M2（1/5/2）范围大（±57344）但精度糙，适合**梯度**（梯度动态范围大）。
- **约束**：两者都需 Hopper 的 E4M3/E5M2 张量核心；范围不足会溢出、尾数不足会损失精度，所以要分场景选型 + 高精度累加。

**Q13. 权重、激活、KV Cache 量化哪个最敏感？为什么 W8A16 省显存不省算？**
- **机制**：权重静态、可离线量化（最稳）；激活逐 token 动态、有离群值（最敏感，需动态量化/SmoothQuant）；KV 是中间结果、读多写少（相对安全，长上下文刚需）。**算力红利只在权重+激活同时量化（W8A8/FP8）才兑现 2× GEMM**，W8A16 只量权重，Tensor Core 仍以 FP16 激活算，所以只省显存不省算。
- **约束**：激活量化最易崩；KV 量化有长序列累积误差；W8A16 的「省显存」≠「省算」。

### 1.3 缓存类

**Q14. Prefix Cache、语义缓存、结果缓存的正确性边界分别是什么？**
- **机制**：Prefix Cache 精确 token 前缀匹配 → 复用 KV（**无损**，同模型同前缀的 KV 是确定性的）；语义缓存按 embedding 相似度复用相近回答（**近似**，相似 ≠ 等价，会返回错误答案）；结果缓存完整 prompt 匹配 → 复用输出（**条件正确**，只在确定性 + 无外部状态时安全）。
- **约束**：语义缓存**绝不用于事实性/参数化/时效查询**；结果缓存要求 `temperature=0` + 无时空依赖；Prefix Cache 只对字面前缀生效。

### 1.4 路由类

**Q15. 模型路由的静态规则 vs 分类路由各有什么约束？失败回退怎么做？**
- **机制**：静态规则路由用「任务类型/上下文长度/风险/预算」的硬阈值分派到快速/标准/高能力三档；分类路由训练一个轻量分类器按 embedding/特征预测难度再分派。
- **约束**：静态规则可解释、零训练、但阈值难调、边界生硬；分类路由自适应但需训练数据、低置信度时不可靠。**失败回退**：分类置信度低或超时/报错 → 升级到高能力档重试 → 仍失败降级到快速档给可用答案并标记；预算超限 → 强制降级快速档。

## 2. 质量—延迟—成本决策表

> 定义三档模型，把「质量/延迟/成本」和「适用任务」落成一张可路由的决策表。

### 2.1 三档模型定义

| 档位 | 代表模型（本周范围） | 质量 | 延迟 | 成本（每 1M token 相对量级） | 典型配置 |
|---|---|---|---|---|---|
| **快速档** | Kimi Linear 48B-A3B、蒸馏小模型（1.5B–7B） | 中低 | 极低（线性注意力解码快） | 极低 | 无思考、FP8/INT4 量化、短上下文 |
| **标准档** | DeepSeek-V3（蒸馏 32B / 稠密）、Qwen 32B 级 | 中高 | 低 | 低 | 无/浅思考、W8A8、标准上下文 |
| **高能力档** | DeepSeek-R1、Kimi K2.5 Thinking / Agent、k1.5 Long-CoT | 高 | 高（长 CoT） | 高 | 思考模式、256K 上下文、agent 编排 |

### 2.2 质量—延迟—成本三维取舍

| 维度 | 快速档 | 标准档 | 高能力档 |
|---|---|---|---|
| **质量** | 简单任务够用，复杂推理/多步 agent 掉链 | 覆盖多数日常任务 | 复杂推理、多步工具调用、长上下文 SOTA |
| **延迟** | 首 token 快、生成快 | 中等 | 长 CoT 思考、TTFT/总时长显著更长 |
| **成本** | 便宜，可承受大量调用 | 适中 | 贵，输出 token 多（思考链）且单价高 |

### 2.3 决策表：任务特征 → 档位

| 任务特征 | 风险/后果 | 预算 | 路由到 | 理由 |
|---|---|---|---|---|
| 短问答、改写、摘要 | 低 | 紧 | **快速档** | 简单任务高能力档是浪费 |
| 一般问答、代码补全 | 低 | 中 | **标准档** | 性价比最高 |
| 复杂推理、数学、长代码 | 中 | 中 | **高能力档** | 标准档质量不够 |
| 多步 agent、工具编排 | 高 | 宽 | **高能力档（Agent）** | 需要自主规划与工具 |
| 事实性/合规/医疗 | 高（错一次代价大） | 宽 | **高能力档** + 结果不做语义缓存 | 正确性优先 |
| 长上下文检索/文档 QA | 中 | 中 | **标准档**（或 Linear 快速档） | 线性注意力长上下文便宜 |

**核心原则**：**按「任务难度 × 错误代价 × 预算」选档**，而不是一律用最强模型——因为高能力档的延迟与成本（长 CoT、高单价）对简单任务是纯浪费。

## 3. 为什么「量化后吞吐提升」不等于「所有任务成本都下降」？

> 这是把「吞吐」和「成本」两个不同量纲混为一谈。吞吐是「单位算力服务的 token 数」，成本是「完成一个任务的端到端花费（含质量损失）」。

### 3.1 吞吐提升的真相

量化（尤其 W8A8/FP8）确实提升**吞吐**：显存减半 → 单卡能装更大 batch → 每秒更多 token；带宽下降 → 每 token 算力/内存更快。所以「推理吞吐」这个指标上升是真实的。

### 3.2 但「任务成本」有三个吞吐覆盖不到的项

1. **质量损失 → 返工/兜底成本**：量化（尤其 INT4/低 bit）会降精度，对**复杂推理、长上下文、事实性**任务可能产生错误。错误 → 重试、人工介入、或升级到更贵的高能力模型兜底。**省下的推理费，被一次重试或一次升级吃掉甚至倒贴**。
2. **硬件门槛 → 不是所有卡都提速**：FP8 要 H100+、BF16 要 A100+、INT4 要新架构。在**老卡上跑 FP8 只能软算，反而更慢**——「量化提速」是条件成立才有的结论。
3. **任务类型 → 收益不均衡**：简单任务量化几乎无损，成本真降；**难任务量化丢精度**，为保持质量要么不量化、要么加量补偿，端到端成本反而升。

### 3.3 一句话结论

> 量化提升的是「**推理吞吐**」（每 token 的算力/显存成本），但「**任务成本**」= 推理费 + 质量损失导致的返工/升级/人工成本。对**精度不敏感、简单、可并行**的任务，吞吐提升 ≈ 成本下降；对**精度敏感、难、错一次代价高**的任务，量化的质量损失会通过返工和兜底把成本抬回去，甚至更高。

### 3.4 落到决策的判据

- 先问「这个任务的**错误代价**多大」：代价低 → 大胆量化（INT4/W4A16 换成本）；代价高 → 保守量化或 FP8（几乎无损）。
- 再问「**硬件**支持吗」：老卡别硬上 FP8/INT4。
- 最后用**第 8 周评测集**实测：量化前后的「成功率 × P95 延迟 × 单任务费用」三者一起看，而不是单看吞吐曲线。

## 4. 路由实验的可复现性与失败回退策略

> 对应计划「编码实验」第 2–5 条：建立路由特征、实现静态规则路由 + 模型分类路由、用第 8 周评测集对比、输出指标与错误案例。这里给的是**可复现规范**与**失败回退策略**（验收要求）。

### 4.1 实验目标

对比三种策略在**同一评测集**上的「成功率 / P95 延迟 / Token 数 / 费用 / 路由错误案例」：

1. 固定大模型（高能力档全量）；
2. 固定小模型（快速档全量）；
3. 动态路由（静态规则版 / 分类版，两版都测）。

**要验证的假设**：动态路由能否「接近大模型的成功率、接近小模型的成本」，以及路由错误（该升级没升级、该降级没降级）发生在哪。

### 4.2 可复现规范（固定项清单）

| 维度 | 固定项 |
|---|---|
| **评测集** | 复用第 8 周 `EvaluationHarness`（Task–Trial–Grader–Trace–Outcome），`run_eval.py` 的 `suite` 与 `--tasks` 路径固定；评测集版本化（git tag + checksum） |
| **模型与量化** | 三档模型的 checkpoint 版本、量化配置（FP8/INT4）、temperature、max_tokens、seed 全部写死 |
| **路由特征** | 任务类型、上下文长度、风险等级、预算上限、历史失败标记（五维，来自计划） |
| **成本模型** | 每档模型每 1M 输入/输出 token 单价写死；费用 = Σ token × 单价 |
| **评测协议** | 每任务多 trial（沿用第 8 周 trial 统计），LLM-as-Judge 与人工抽检双重判定 |
| **日志** | 每个请求记录「特征 → 路由决策 → 模型 → 结果 → 是否该升级/降级」，用于路由错误案例回放 |

### 4.3 失败回退策略（必须明确）

路由的失败有两类：**路由选错** 与 **执行失败**。回退策略如下：

1. **分类低置信度 → 升级**：分类路由的难度预测置信度低于阈值，或历史该特征组合失败率高 → 直接升级到高能力档，宁贵勿错。
2. **执行超时/报错 → 升级重试 → 降级兜底**：单次调用超时或异常 → 升级到高能力档重试一次；仍失败 → 降级到快速档给一个**可用的近似答案**并打「降级」标记（保证可用性优先）。
3. **预算超限 → 强制降级**：累计费用接近预算上限 → 后续请求强制降级快速档，保证不超预算。
4. **风险/合规任务 → 永不降级、不做语义缓存**：高风险任务（医疗/合规/事实性）锁定高能力档，禁止回退到近似答案。
5. **回放与修正**：从日志里抽「该升级却降级」的错误案例，回放对比，反哺分类器的阈值或规则表；每次修正都要在固定评测集上重跑，避免「针对案例过拟合」。

### 4.4 输出与验收口径

- 输出五类指标：**成功率、P95 延迟、总 Token、总费用、路由错误案例**（按「误降级/误升级」分类）。
- 验收：动态路由**成功率不低于固定大模型的 95%**、**费用不高于固定大模型的 60%**（阈值可按任务调整）；失败回退策略在注入「超时/预算超限/低置信度」故障时能正确触发。

## 5. 本文结论

- **面试题**：14 道覆盖 DeepSeek/Kimi、量化、缓存、路由，全部走「产品名 → 机制 → 约束」——面试里只背产品名不算会，要能说出每个机制的**代价/适用边界**（MLA 的额外算力、DSA 的近似、KDA 的召回弱、量化的硬件门槛）。
- **质量—延迟—成本决策表**：三档模型（快速/标准/高能力）+ 任务特征 → 档位映射，核心是「按任务难度 × 错误代价 × 预算选档」。
- **量化成本辨析**：吞吐提升是「每 token 算力成本」下降，任务成本还要加「质量损失 → 返工/升级」这一项；精度敏感任务上量化可能反而更贵。
- **路由实验**：可复现靠「固定评测集/模型/成本模型/日志 + 多 trial + 双重判定」；失败回退靠「低置信度升级、超时升级→降级兜底、预算强制降级、高风险锁定、案例回放修正」五条。
